# 音乐伙伴第一版版本总结

更新日期：2026年10月11日。对应代码基线：`46affd7`。

这是一款面向吉他指弹学习者与教师的本地网页原型：用户用文字描述想听的音乐，软件调用阿里云百炼千问生成简单和声加旋律的小作品，提供六线谱、试听和下载。

当前核心功能已实现，历史版本有真实页面验收记录；最新版自动检查通过，但完整正式页面流程仍待复验。详见[验收报告](音乐伙伴三天原型验收报告.md)。

## 1. 本版做了哪些功能

- **文字创作**：填写音乐描述，或点击三个示例填入描述，再主动开始生成；无需登录。
- **真实AI生成**：使用北京地域百炼接口与`qwen-plus`，先规划和声、再逐小节创作。并非固定曲目或随机模板替代。
- **音乐与演奏检查**：检查节拍、音符结构、功能和声与终止、标准定弦指型、品位跨度、换把及音频时长。
- **六线谱展示**：使用alphaTab显示吉他谱，将同一作品导出为PDF。
- **试听**：将作品转为MIDI，再通过本机音色工具合成、编码为MP3，支持播放、暂停及作品切换。
- **整段重新生成**：保留旧作品的速度和调性，改变音乐内容；等待或失败期间保留旧作品，成功后一起替换谱面、音频和下载入口。
- **下载**：分别下载MP3和PDF，不需要ZIP解压。
- **任务状态与进度**：显示生成进度和失败信息，支持取消，设置提交起算600秒的等待上限。
- **当前会话恢复**：生成中或成功后刷新可找回当前任务；提交结果不确定时可点击“恢复当前任务”，避免重复创建收费任务。
- **预算与故障记录**：每次模型请求检查本地预算，记录调用凭据、失败步骤和估算费用；失败时不交付半成品。
- **本地启动与诊断**：启动器构建网页、启动正式服务；提供环境和各模块诊断工具。

正常流程为：

`文字描述 → AI和声规划 → AI逐小节创作 → 音乐与指型检查 → MIDI/音频/PDF导出 → 展示、试听、下载`

AI生成的是结构化音乐内容；实际MP3由本机合成工具制作，并非大模型直接输出吉他录音。

## 2. 已知限制与尚未完成的部分

### 已确认的产品限制

1. 仅支持标准定弦吉他指弹，简单和声加旋律；不支持其他乐器、特殊定弦和打板技巧。
2. 速度限定为**60–120 BPM，含边界**，允许十六分音符；BPM只是主要难度参考，不能代表全部演奏难度。
3. 最终MP3不超过60秒，包括尾音和编码影响；生成规划使用57秒演奏预算预留空间。
4. 优先前五品，最高第七品；第六、七品音符占比不超过10%，按弦跨度和相邻最低按弦品位移动均不超过3品，空弦不计跨度。
5. 当前分阶段生成更保守：主要使用调内三和弦、和弦音旋律和持续和弦伴奏。复杂非和弦音、七和弦、复杂分解伴奏与跨小节延音未开放给新生成流程。
6. 可用调性受标准定弦、音域、指型和终止检查共同限制；不支持的明确调性会拒绝，不会偷偷转调。自然语言速度、调性的识别不能覆盖所有表达方式。
7. 重新生成不支持变速、转调，也不支持只选择几个小节修改。
8. 本版不含账号、社区、永久作品库、哼唱、学生管理、练习进度、每天练习计划、自动演奏评价或专业编曲编辑。
9. 当前交付为macOS本地服务和电脑Chrome页面；安卓打包、移动端适配和公网部署没有完成。

### 验收和稳定性限制

- 最新版本160项后端测试、19项前端测试通过；早期真实生成、试听、谱面与下载通过实测。
- 分阶段生成上线后，最新版普通提示词到正式页面MP3/PDF交付的全流程，仍需重新验证。独立样本的音乐或音频成功，不等于整条交付链通过。
- 历史出现过连续生成失败；当前没有足够数据承诺稳定成功率、典型等待时间或每首实际费用。
- 分阶段调用次数较多，可能增加等待时间与费用。每个规划或小节最多尝试两次；传输层还有有限重试，不应理解为整首只调用一次模型。
- 听感已经得到用户改善反馈，但自动乐理检查不能保证每首都动听、符合主题或能激发练习动力。最新版代表作品仍需要人工试听与弹奏。
- 取消是协作停止，正在进行的网络读取或导出可能等到下一检查点才停止；不保证即时停止或退费。
- 预算是本地估算保护，不是百炼账单或账号级硬上限；未知费用会保守预留。
- 刷新恢复依赖当前标签页的会话存储及服务端文件。关闭标签页、清理浏览器数据或删除临时文件可能导致入口失效，不是永久保存。

## 3. 怎么运行项目

### A. 当前这台电脑：推荐方式

已有依赖与密钥配置，无需重新安装或覆盖`.env`。

1. 关闭旧服务：在原启动窗口按`Control+C`，等其退出。页面上的取消按钮用于取消创作，停止服务不是取消创作的替代操作。
2. 在Finder打开桌面的`music companion`文件夹，双击`启动音乐伙伴.command`；或者打开终端执行：

```bash
cd "/Users/ming/Desktop/music companion"
bash "启动音乐伙伴.command"
```

3. 保持终端窗口打开。启动器先构建前端，再启动后端，不会因启动而调用AI。
4. 使用Chrome打开：<http://127.0.0.1:8000/>。
5. 看到音乐描述输入框、三个示例、作品与试听下载区域，说明网页入口已启动。初始没有作品是正常状态。
6. 可打开<http://127.0.0.1:8000/api/health>确认返回`status: ok`。这只证明服务可访问，模型、音色与PDF还需要实际生成验证。
7. 输入描述并开始生成会产生模型费用。成功后应同时出现六线谱、播放器、MP3下载和PDF下载入口。

若提示8000端口被占用，应先停止旧服务再启动；启动器不会自动关闭其他程序。更新后端要重启，更新网页要重新构建；重新运行启动器会完成构建。

### B. 已安装环境下，手动构建和启动

在项目根目录依次执行：

```bash
cd "/Users/ming/Desktop/music companion/frontend"
npm run build
cd ../backend
.venv/bin/python -m uvicorn app.main:app --host 127.0.0.1 --port 8000 --no-access-log
```

保持窗口打开，再访问同一8000地址。正式方式不需要另开Vite。当前电脑如果系统没有`npm`，优先使用A方式，启动器具有本机工具回退逻辑。

### C. 换电脑或首次安装

安装Node.js/npm与Python。当前验证的Node为24，现有Python虚拟环境为3.9；换用Python版本或系统后须重新验证。不要直接复制旧电脑的虚拟环境。

在新电脑的项目根目录执行：

```bash
python3 -m venv backend/.venv
backend/.venv/bin/python -m pip install -r backend/requirements-lock.txt
cd frontend
npm ci
cd ..
cp .env.example .env
```

`cp`仅用于首次创建配置，已有`.env`时不要覆盖。根目录没有`package.json`，**前端依赖安装必须进入frontend**，不能在根目录直接执行`npm install`。

随后完成这些本机配置：

1. 在根目录`.env`填写`DASHSCOPE_API_KEY`，保留已验证的北京百炼接口与模型配置；密钥不要发到聊天或放进前端。
2. 按[依赖工具与参数记录](依赖工具与参数记录.md)准备FluidSynth、FFmpeg、SoundFont与中文字体，填写`.env`对应工具路径。仅安装Python和npm依赖不足以生成音频与PDF。
3. 安装PDF打印浏览器：

```bash
PLAYWRIGHT_BROWSERS_PATH="$PWD/.tools/browsers" backend/.venv/bin/python -m playwright install chromium
```

4. 检查环境：

```bash
backend/.venv/bin/python backend/scripts/check_environment.py --sound-check --play
```

应显示音频工具、音色、浏览器和字体可用。听到六根弦的诊断音只代表音频工具可用，不是AI创作成功。Chromium负责后台打印PDF，用户仍用Chrome访问页面。

最后使用A方式启动。其他系统可能需要调整Python锁定文件中的平台包；工具路径、字体和音色许可都要重新核对。

## 4. 以后接着改，需要特别注意什么

### 音乐结构是共同底稿，不能只改一处

`backend/app/schemas/`与`frontend/src/types/composition.ts`定义音乐数据。生成、检查、MIDI、六线谱和PDF必须使用同一份内容；改字段或时值表达时，要一起检查这些消费者，否则可能出现“谱和音不一样”。

### 生成效果要同时改规则与提示词

`backend/app/providers/staged.py`负责规划与逐小节创作；`music/harmony.py`、`validation.py`、`fingering.py`负责验收。只要求模型写得更复杂，却不更新允许范围和验证规则，会造成连续拒绝；放宽检查也不能拿不合格作品当成功。

BPM边界统一放在`music/limits.py`。增加新调性、非和弦音、七和弦、分解伴奏或延音，先明确规则、检查实际指型，再用真实样本试听与弹奏。不要仅凭自动测试通过判断音乐质量。

### 节拍、小节和延音容易连带出错

音符密度增加、十六分音符、跨小节延音或多声部变化会影响节拍总和、同弦重叠、谱面解析、MIDI和实际音频时长。历史已有延音结构和alphaTex声部解析问题。谱面转换在`music/alphatex.py`，音频路径在`midi.py`、`phrasing.py`和`audio.py`；改后应同时听音与看谱。

### 重新生成与恢复是一套状态协议

`frontend/src/hooks/useGeneration.ts`、`api/currentSession.ts`与后端`jobs.py`、`api.py`共同管理旧作品、待生成任务和请求编号。不要在重试时随意换新编号，否则可能重复收费；不要在新作品完全就绪前清掉旧作品或只替换音频。

同编号同内容可找回原任务，同编号不同内容必须拒绝。改取消和任务交付时，要保留共用锁与最终检查，防止已经取消的任务又变成成功。

### PDF依赖本机浏览器与正式页面

`music/pdf.py`与前端打印页需要正确的浏览器路径、字体和打印服务地址。默认正式端口为8000；换端口或换部署方式要同步打印配置。诊断页面通过不代表正式页面通过，生成了文件也不代表它不是空白或被裁切。

### 时长看最终MP3，不能只看音符总时值

尾音与编码会增加实际时长。保留演奏预算与最终文件检查；不要为凑60秒直接裁掉主和弦结尾。

### 不要删密钥配置和费用台账来“清理”

`.env`、`.tools/`与`runtime/`是本机配置、工具和产物，不随Git迁移。`runtime/ai/`保存预算台账；删除会破坏累计费用保护。`runtime/jobs/`不是永久作品库，重要作品应及时下载。已有清理脚本只用于指定失败诊断目录，应先预览再执行。

### 当前部署与存储是原型方案

后台任务、文件锁、本地文件、当前标签页恢复适合单机原型。若以后做多人公网产品，需要重新设计用户身份、作品归属、数据库、对象存储、任务队列、费用配额与访问权限，不能简单开放本机端口当作完成上线。

启动器含当前电脑的Codex Node回退路径；系统有Node时优先使用系统工具。迁移、打包时应替换本机回退路径并处理音频工具、字体和音色许可。Android前端封装不会自动解决Python、音频合成和PDF后台运行问题，需另定运行架构。

### 文档与依赖也要维护

保留`frontend/package-lock.json`与`backend/requirements-lock.txt`，不要随意升级alphaTab、Playwright或音频工具，升级后要复验谱面和导出。

README中“刷新丢失作品入口”的旧描述已被新版当前标签页恢复功能取代；其他历史诊断文档也可能记录旧版本结论。阅读时结合提交版本，以最新修复说明和验收报告为准，不要把历史通过等同于当前全部通过。

## 5. 建议的继续开发顺序

1. 先复验最新版正式Chrome流程：普通提示词生成、试听、谱面、重新生成、下载、刷新与取消。
2. 记录成功与失败样本，确认失败阶段，再改生成稳定性；不要重复点击掩盖问题。
3. 在用户试听与试弹基础上逐步扩展音乐规则和伴奏表现，每次只改一组规则。
4. 明确下一版的用户范围后，再考虑作品库、局部编辑、教学管理或安卓封装。

