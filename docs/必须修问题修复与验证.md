# 必须修问题：修复与验证

本轮依据此前自查的六项问题，只处理生成恢复、运行边界与故障追踪，不新增社区、作品库或练习管理。此前尚未提交的分阶段生成实现随本轮一并保留；不把它的独立音乐检查结果当作新版正式页面的完整音乐交付验收。

## 状态

1. 刷新恢复：已实现。sessionStorage只保存当前标签页的描述、当前作品任务编号和未结束提交的编号；恢复后读取服务端真实数据，不缓存谱面/音频副本。生成中刷新恢复同一任务，重新生成时先恢复旧作品。关闭标签页、清理浏览器会话或清理服务端临时文件可能使恢复失效，不是永久作品库。
2. 提交不确定的恢复：已实现。发送前保存客户端生成的请求编号，后台将其作为任务编号并核对描述/来源摘要；同编号同内容返回原任务，不重复收费生成，不同内容拒绝。页面提供“恢复当前任务”，先GET；404时只重发同编号的原描述。明确拒绝的提交允许新提交。
3. 等待上限/取消/进度：已实现。提交起计600秒，包括排队；模型流接收、每次调用前、小节、导出阶段和正式交付前检查。采用协作停止，正在进行的网络读取或导出需要到下一个检查点/现有工具超时才能结束，不保证点击即瞬时停止或退费。取消标记与交付使用同一文件锁；迟到的提交也不会重启已取消编号。排队取消不调用模型。逐小节进度保存并显示。
4. BPM范围：已实现。用户确认60–120 BPM，包含两个边界。和声规划Schema、模型指令和最终音乐交付检查均限制范围；首次描述中常见明确BPM写法超出范围时，在模型调用前拒绝。重新生成保持原BPM优先于文字改速要求；旧作品超出范围时拒绝重新生成并保留其原速度与现有文件，不自动变速。
5. 可用调性：已实现。从实际标准定弦/指型/属到主终止的候选计算可用调性清单，给规划模型明确范围。常见明确调性写法（B大调、降B小调、F# minor等）先检查；不支持时不发送模型请求，不偷偷转调。支持的明确调性须与输出匹配。重新生成优先原作品调性，不被文字中的转调要求改写；不支持的旧调性明确保留旧作品并拒绝。未承诺识别所有自然语言调性表达。
6. 失败调用记录：已实现。每步骤成功/拒绝时写入manifest，记录步骤与小节编号。网络、预算、取消和截止失败附上已有凭据，再由流水线保存；未知费用仍保守保留于原预算台账。manifest的estimated_cost仅为有凭据请求的估算汇总，不是供应商账单或未知费用总额；实际费用核对仍看budget.json与供应商账单。

## 正式入口手动验证

后端重启并由启动器重新构建后，访问http://127.0.0.1:8000/：

1. 普通描述生成中刷新：应恢复描述与原任务，不能创建第二个生成任务。
2. 成功作品刷新：应显示“已恢复当前作品”，作品编号、谱面、试听和两个下载入口保持一致。
3. 重新生成时取消：应先提示正在取消，再显示已取消，旧作品仍可用；允许新提交。
4. 网络恢复后点击“恢复当前任务”：应查原任务；未接收时重发同编号，不另建收费任务。
5. 首次生成输入“B大调，四小节”：应明确当前不支持，不能交付别的调性；此项不能拿已有作品的重新生成测试，因为重新生成保持原调性优先。
6. 正常失败、取消、预算不足后查看runtime/jobs对应manifest：应有先前步骤和失败阶段；未知费用查看runtime/ai/budget.json，不删除台账。

BPM范围已确认60–120；整曲AI生成到MP3/PDF的新版正式页面验收仍未由本轮诊断代替。
