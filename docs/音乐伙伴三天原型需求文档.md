# 音乐伙伴三天原型需求文档

更新日期：2026-10-09

版本：三天开发原型版。

范围说明：本文件依据已确认的“仅吉他、优先指弹”方向，以及用户接受的三天版本删减建议整理。三天原型开发以本文件为准；原《音乐伙伴需求文档.md》保留为较完整的产品范围参考，其中的社区、哼唱、局部生成等功能不自动进入本次开发。未决定的参数明确标为待确认，不自行设定默认值。

## 1. 产品定位与验证目标

一款通过 AI 理解提示词并参与音乐创作，帮助吉他指弹学习者生成短作品、看六线谱并试听的网页原型。

本次重点验证：用户是否喜欢生成的小作品，以及是否愿意拿起吉他练习。生成次数或网页停留时间不能单独证明这个目标成立。

本次不承诺覆盖全部指弹技巧、全部难度或任意音乐风格，也不承诺已经提高学习效率。优先保证谱与声音一致、作品在限定范围内可演奏。

## 2. 目标用户

- 主要用户：希望创作并练习自己喜欢的小作品的吉他指弹学习者，不限定年龄。
- 次要用户：吉他教学者，可使用相同页面生成短作品并判断是否适合教学，不提供独立教师流程。
- 首版仅支持吉他。
- 首批作品采用简单和声加旋律的形式，使用吉他标准定弦，不支持打板等打击类指弹技巧。难度主要参考 BPM，其他条件相近时速度越低通常越容易、越高通常越难；仍保留基本可演奏性检查。优先前五品，允许少量更高品位和十六分音符。

## 3. 最核心的使用场景

学习者进入网页，无需注册或完成水平测评，输入自己想要的音乐听感，也可参考示例提示词。软件生成一段短的吉他指弹作品，并展示六线谱和对应音频。用户看谱、试听；若不满意，可修改文字要求并重新生成整段作品；满意后下载对应音频与六线谱，再自行练习。

教师使用同一流程获取教学素材，在线下判断作品和学生的适配性，不在产品中管理学生或布置作业。

核心流程：

```text
输入文字想法
    ↓
生成短吉他指弹作品
    ↓
查看六线谱 + 播放对应音频
    ↓
不满意：修改文字要求 → 重新生成整段
满意：下载音频与六线谱 → 自行练习
```

## 4. 核心功能清单

### F1. 文字创作输入

- [ ] 支持用户以文字描述音乐想法。
- [ ] 提供少量示例提示词，减少不知道如何输入的负担。
- [ ] 用户可以自行修改文字后提交。
- [ ] 不要求先注册、完成专业问卷或演奏测试。
- [ ] 不做多轮创作引导问答。

示例提示词的具体内容与实际支持的生成范围需匹配，不展示无法兑现的风格或复杂技巧承诺。

### F2. 生成短吉他指弹作品

- [ ] 接入 AI 模型，根据用户提示词生成一段短的吉他指弹作品；AI 创作是本次必做功能。
- [ ] 模型实际参与音乐内容创作，不能仅识别关键词后随机返回模板作品。
- [ ] 按时长限制作品长度，单首作品演奏时长不超过 1 分钟（60 秒）；不要求每首都达到 1 分钟。
- [ ] 首批作品只支持简单和声加旋律的形式。
- [ ] 使用吉他标准定弦：从六弦到一弦为 E2、A2、D3、G3、B3、E4。
- [ ] 不支持打板等打击类指弹技巧。
- [ ] 难度主要参考 BPM，不新增难度等级界面；优先前五品，允许少量更高品位和十六分音符。
- [ ] 保留跨度、换把与同弦冲突等基本可演奏性检查，不把低 BPM 当作一定可演奏的保证。
- [ ] 作品内部速度与调性保持统一。
- [ ] 关注旋律与伴奏的配合、弦号和品位分配、跨度及换把负担，不能以单音旋律代替指弹功能。
- [ ] 在确认的生成范围内检查基本可演奏性，不能只以“能够播放”作为合格标准。
- [ ] 生成过程中显示处理中状态；失败时给出清楚说明并允许重试。

音乐规则和模板可用于约束、辅助模型创作及检查吉他可演奏性，但不能替代 AI 生成。模型提供商确定为阿里云百炼千问；开发测试预算上限 200 元；具体型号和接入配置在测试时确定。模型调用失败时明确提示失败，不将纯规则或固定模板结果冒充 AI 生成结果。

### F3. 查看六线谱与试听

- [ ] 展示当前作品的吉他六线谱，包含演奏所需的弦号、品位和节奏信息。
- [ ] 提供当前作品的音频播放与暂停。
- [ ] 乐谱与音频来自同一份音乐数据，表达同一个作品版本。
- [ ] 不要求真人录制音频；若使用合成音色，应如实说明。
- [ ] 暂不做跟谱高亮、循环选段、变速播放等额外播放功能。

### F4. 整段重新生成

- [ ] 用户可修改文字要求并重新生成整段作品。
- [ ] 重新生成仍遵守当前确认的作品长度、复杂度与可演奏性范围。
- [ ] 每个新作品内部保持速度与调性统一。
- [ ] 新作品完成后，乐谱与音频同步展示，不混用新旧结果。
- [ ] 不支持按小节选择、局部重新生成或直接编辑音符。

整段重新生成必须保留当前作品的速度（BPM）和调性，只改变音乐内容；不要求保留原旋律主题。

### F5. 下载音频与乐谱

- [ ] 支持下载用户满意作品的音频与吉他六线谱，两类内容均须提供。
- [ ] 下载内容对应当前展示的同一作品版本。
- [ ] 不以浏览器本地作品库作为本次保存方案，不建立云端账号或作品库。
- [ ] 明确说明下载内容及如何查看或播放；文件保存位置由浏览器及用户的下载设置决定。
- [ ] 音频下载格式为 MP3。
- [ ] 六线谱下载格式为 PDF。
- [ ] 分别提供“下载 MP3”和“下载 PDF”两个按钮，不做 ZIP 打包下载。

本次只做下载留存，不做作品分类、搜索、历史版本或跨设备同步。

### F6. 演示环境与后续平台方向

- [ ] 首次演示使用电脑端 Chrome 浏览器。
- [ ] 三天原型以电脑浏览器中的核心流程为验收范围。
- [ ] 安卓系统打包是后续方向，不列入三天原型交付；打包方式与安卓适配范围待后续确定。

## 5. 这一版先不做

### 从较完整产品范围中延期

- 哼唱输入及旋律识别。
- 多轮创作引导问答。
- 谱面按小节选择与局部重新生成。
- 社区分享、点赞与评论。
- 云端账号、云端作品库及跨设备同步。
- 专业水平定位、详细的难度匹配与教师填写学生水平流程。
- 独立教师页面、角色区分和专门教学操作。

简单水平选项不作为本次必做功能；若后续确认加入，需明确选项与生成范围，不默认承诺精确难度匹配。

### 延续此前明确不做或未纳入的部分

- 吉他以外的乐器。
- 自动评价音准、节奏等演奏表现。
- 练习进度记录、每日练习计划和自动学习目标推荐。
- 学生管理、作业布置及教师查看学生进度。
- 专业编曲编辑、多乐器合奏教学和虚拟角色聊天。
- 独立手机应用或桌面应用，以及安卓打包；安卓是后续方向。
- 打板等打击类指弹技巧和非标准定弦作品。
- 站外发布、独立伴奏文件，以及尚未确认的其他吉他演奏形式功能。

这些项目不属于三天原型验收范围。延期不等于永久删除，也不自动承诺某个后续版本的上线日期。

## 6. 最低交付与验收条件

1. 用户无需账号和测评，即可输入文字并发起真实 AI 模型生成；模拟数据或固定模板不能作为该功能的验收结果。
2. 生成作品演奏时长不超过 60 秒，采用标准定弦的简单和声加旋律，不包含打板等打击类技巧。
3. 六线谱可阅读，音频可播放，两者对应同一份作品数据。
4. 作品经过基本演奏约束检查，并由具备吉他指弹能力的人试奏或审阅代表样例。
5. 用户能修改文字要求并重新生成整段，显示结果不会混用新旧版本。
6. 用户能下载当前作品的 MP3 音频与 PDF 六线谱，两者与网页显示的作品一致；MP3 可正常播放，PDF 可正常打开且谱面清晰可读。
7. 生成失败或保存失败时有明确提示，不能把失败显示为成功。
8. 在电脑端 Chrome 浏览器中，页面无需依赖延期功能，即可完成核心流程。

作品时长、形式、定弦和打击类技巧排除范围已确认。下载格式已确认为 MP3 音频与 PDF 六线谱；目标浏览器为 Chrome，难度主要参考 BPM；最终 MP3 文件总时长不得超过 60 秒。

## 7. 三天开发建议顺序

以下是执行优先级建议，不是已经验证的工期保证。

### 第一天：验证乐谱与音频链路

先用同一份指弹音乐数据生成可读六线谱与对应音频，检查音符、节奏、弦位和基本演奏可行性。样例用于验证基础能力，不能冒充用户实时生成结果。

### 第二天：接入文字与受约束生成

完成真实模型接入、文字输入、AI 创作、约束检查和结果展示，让用户要求在所支持的范围内影响作品。优先验证可演奏性，不追求大量风格或复杂技巧。

### 第三天：完成核心流程并试用

完成整段重新生成、音频与六线谱下载、处理中与失败状态，邀请实际指弹学习者或教师试用。

如果第一天谱面与音频链路仍未打通，优先解决这一问题并重新确认生成范围，不把社区、哼唱或局部编辑加回开发计划。

## 8. 已确认参数与剩余待确认项

### 已确认

1. 作品长度：按时长限制，上限 1 分钟（60 秒），不是按固定小节数限制。
2. 作品形式：首批只支持简单和声加旋律。
3. 定弦与技巧：吉他标准定弦；不支持打板等打击类指弹技巧。
4. 保存方式：分别下载 MP3 音频与 PDF 六线谱，使用两个下载按钮，不做 ZIP 打包。
5. 首次演示：电脑端 Chrome 浏览器。后续打包面向安卓系统，不属于三天交付。

6. AI 提供商：阿里云百炼千问，具体型号待确认。
7. 难度主要参考 BPM；指型优先前五品，允许少量更高品位和十六分音符。

### 尚待确认，不自行设置默认值

- 少量更高品位的具体范围、按弦跨度与换把负担，仍需测试和确认。
- 千问具体模型型号、实际生成表现、账号地域及接入凭证在测试时确定；总预算不超过 200 元。

安卓打包技术路线在后续阶段确定，不要求现在为它增加三天原型功能。

## 9. 试用时观察什么

- 用户能否理解文字输入方式并顺利获得作品。
- 用户是否觉得作品好听、是否愿意尝试演奏。
- 试奏时是否出现明显指法困难或谱面与音频不一致。
- 用户是否能完成重新生成及音频、乐谱下载。
- 用户放弃流程的具体原因是什么。

本次不建立完整的练习追踪系统，可通过实际试用观察与访谈收集反馈。是否更愿意长期练习，需要后续持续验证。

## 最新参数确认（2026-10-09）

- AI 开发测试总预算不超过人民币 200 元。千问型号、账号地域和凭证在测试接入时确定；密钥仅放本机服务端配置。记录实际调用与重试消耗，预算检查在调用前执行；供应商实际计费也需核对，不把无统计的重试视为免费。
- 指型优先选择空弦及前五品，允许少量更高品位，并非严格限定第 0—5 品。更高品位上限和“少量”的具体判定尚未量化，不自行设定数字；仍需检查跨度、换把和同弦冲突，并人工审阅样例。
- 允许十六分音符，不因此默认启用未确认的复杂节奏或技巧。
- 难度主要参考 BPM：其他条件相近时，BPM 越低通常越容易，越高通常越难。这替代此前“音符密度为主要指标”的要求；首版不新增难度等级或水平选择界面，也不以音符密度计数口径作为开发前置条件。BPM 不能代替节奏与指型的可演奏性检查。
- 最终 MP3 文件总时长不得超过 60 秒，包括尾音和编码影响；生成时预留尾音空间，编码后检查实际文件时长。不通过截断尚未结束的音符满足上限。
- 整段重新生成保留当前展示作品的 BPM 和调性，只改变音乐内容；首次生成没有旧作品约束。前端提交当前作品编号，服务端读取旧作品并校验新结果的 BPM 和调性完全一致。失败保留旧作品，成功时谱面、MP3 和 PDF 同步替换；不要求保留原旋律主题。

剩余待确认：测试时选择千问型号/地域并配置凭证；高品位“少量”的上限或比例、可接受的按弦跨度及换把负担。BPM 难度分级阈值不属于当前无等级界面的必做功能。

## 后续确认：首版速度边界

- 用户确认首版新生成作品速度范围为60–120 BPM，包含60与120。
- 该范围是首版生成边界，不是专业演奏难度分级。十六分音符、时长及指型检查继续保留。
- 重新生成仍必须保持旧作品原BPM与调性；旧作品BPM超出范围时明确拒绝重新生成，不自行变速，已有谱面与音频仍可使用。
