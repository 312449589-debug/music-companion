## 使用方式与交付边界

每个编号是一项独立任务，适合一次对话完成并形成一次提交。编号是推荐执行顺序，“依赖”说明真正的前置条件；无直接依赖的任务可调整顺序。完成后将对应复选框勾选，并留下验收结果。任务中的接口和诊断命令是建议的开发约定，不增加产品页面。

技术路线保持 React / TypeScript / Vite + Python / FastAPI / Pydantic；千问参与真实结构化作曲；alphaTab 排谱；mido、FluidSynth、SoundFont、FFmpeg 生成 MP3；Playwright / Chromium 导出 PDF。不改成直接生成音频后扒谱。

最终交付：Chrome 电脑网页，无需账号，输入文字 → 真实 AI 生成标准定弦、简单和声加旋律的指弹作品 → 查看六线谱、试听 → 修改描述并整段重新生成 → 分别下载 MP3 和 PDF。作品演奏时长不超过 60 秒。

静态原型可以使用模拟内容，实际 demo 的 AI 生成功能必须真实接入。原型 README 中“demo 阶段不要求接入真实 AI”的表述不作为开发依据。

三天是时间预算，不是已验证工期。模型输出质量、指型处理和音频/PDF 环境是主要风险；任务未通过时不以模拟数据宣布完成。
