# 音乐伙伴三天原型验收报告

- 报告日期：2026年10月11日
- 验收对象：本地网页版音乐伙伴，面向标准定弦吉他指弹学习者。
- 项目位置：`/Users/ming/Desktop/music companion`
- 当前代码基线：`46affd7`（60–120 BPM范围修复）；此前关键修复为`3756960`（分阶段生成、恢复与取消）。
- 记录方式：汇总已有测试记录、用户反馈，并在本次报告中重新运行后端和前端测试。没有新增收费模型调用。

## 一、验收结论

**结论：部分通过，最终验收待补齐。**

核心功能已实现。早期版本在正式Chrome页面中，已经实测通过真实AI生成、谱面显示、试听、整段重新生成，以及MP3/PDF下载。用户试听反馈从“单调、没有练习欲望”改善为“暂时通过”和“听感好很多了”。

最新版代码的160项后端测试、19项前端测试全部通过。刷新恢复、提交结果不确定时找回任务、取消、等待上限、BPM范围、调性限制和失败记录都有相应检查。

但是，生成方式后来改为分阶段创作，最新版尚未在正式Chrome入口重新完整验证“普通提示词 → AI生成 → 谱面与音频 → 重新生成 → MP3/PDF下载”。独立AI样本通过音乐检查，不能代替这条完整交付链的验收；复用历史文件的诊断页面，也不能算作新曲生成成功。因此本报告不将第一版标记为全面验收通过。

## 二、本次验收的产品范围

本版支持文字提示词与示例提示词，生成简单和声加旋律的吉他指弹片段，展示六线谱、播放音频，支持整段重新生成，以及分别下载MP3和PDF。

已确认的边界如下：

1. 标准定弦：六弦至一弦为E2、A2、D3、G3、B3、E4；不支持打板等打击技巧。
2. 速度为60–120 BPM，包含两个边界；允许十六分音符。
3. 最终音频不超过60秒，包括尾音和编码后的实际时长。生成过程预留尾音空间，不能靠裁掉结尾达标。
4. 优先前五品；最高第七品；第六、七品音符合计不超过10%；同时按弦品位差不超过3，空弦不计；相邻指型最低按弦品位移动不超过3。
5. 音乐要体现功能和声的紧张与解决，结尾落在主和弦与旋律主音，使用动机重复和发展。
6. 整段重新生成保持原速度、原调性，只改变音乐内容；等待和失败期间保留旧作品。
7. 首次演示使用电脑Chrome。安卓打包不在本次验收范围。

账号、社区、永久作品库、哼唱、按小节局部修改、练习进度、每日计划、自动演奏评价、多乐器教学、专业编曲编辑均不属于这版交付要求，不将其缺失计为本版缺陷。

## 三、证据如何区分

本报告使用四类证据，不能互相替代：

- **本次自动检查**：2026年10月11日重新运行，针对当前代码基线。
- **历史真实流程**：实际调用百炼模型，并在Chrome操作或检查真实导出文件；仅证明当时版本和当时样本。
- **受控故障诊断**：人为制造失败、取消、刷新等场景；部分使用历史真实作品，不调用AI。主要证明页面状态和恢复逻辑。
- **用户人工反馈**：指型与主观听感审阅。不能直接证明长期练习动力或学习效率。

历史记录中的“通过”或“未实现”均有版本背景。后来修复会更新当前判断，但不会把历史失败从验收记录中抹去。

## 四、按功能核对

### 1. 首页与输入：完成，历史页面验收通过

无需登录即可进入；可填写描述、点击示例填入文字，再主动开始生成。初始没有作品时，相关试听和下载入口不可用。没有把点击示例当成自动收费生成。

最新版增加输入中的明确速度、调性检查，自动测试通过；正式页面的新增提示仍需复验。

### 2. AI生成与音乐质量：部分完成

真实百炼模型接入已验证，当前采用先规划和声、再逐小节生成的方式，减少一次生成整段结构出错的问题。独立样本通过和声、节拍、指型等检查。

仍缺少最新版普通提示词完整交付的复验，不能认定生成稳定性已经达标。听感有明显改善，但规则通过不等于每首都好听；主题符合度、旋律吸引力仍需要用户逐曲判断。

### 3. 六线谱与PDF：已实现，历史实测通过，最新版完整交付待复验

已有真实作品展示六线谱并导出一页PDF，检查过小节、结尾和页面裁切。失败谱面被明确拒绝，用户确认过“没有空白PDF”。

新版独立导出测试中，PDF所需浏览器进程受到执行环境限制，不能计为新版导出成功，也不能仅凭这一限制认定产品本身一定失败。需通过本机启动器再次验证。

### 4. 音频与播放器：已实现，历史实测通过，最新版页面待复验

真实MP3完成解码和时长检查；播放、暂停、播到结尾，以及替换作品时停止旧音频并重置播放位置均有历史记录。分阶段样本也有真实音频导出通过的记录。

仍需检查新版正式页面是否交付同一首作品的音频和谱面，且最终时长不超过60秒。

### 5. 整段重新生成：已实现，历史实测通过，最新版端到端待复验

历史真实测试中，新旧音乐内容不同，速度和调性保持一致；失败时旧作品仍可使用。文字中要求改速、改调，也不会覆盖重新生成的原作品约束。

最新恢复、取消与旧作品保留逻辑已经通过受控页面诊断，但这次诊断没有生成新音乐，不能替代真实重新生成验收。

### 6. MP3/PDF下载：已实现，历史实测通过，最新版完整交付待复验

两个文件分别下载。历史下载文件与服务端导出文件的字节和SHA256一致；单个文件缺失时，只影响对应下载，恢复文件后可重试，无需重新调用AI。

最新版仍需验证下载的是当前作品，而非上一首作品，且文件可正常播放、打开。

### 7. 失败、恢复、取消与预算保护：完成实现，自动检查和受控诊断通过

重复提交同一请求不会另建生成任务；提交响应丢失后可找回原任务。生成中刷新可恢复当前任务；已有作品刷新可恢复作品。取消和超过600秒等待上限会阻止后续交付；逐小节进度与已有调用凭据被记录。

恢复范围是当前标签页会话和仍存在的服务端临时文件，不是永久作品库。取消属于协作停止，进行中的网络读取或导出可能需要等到检查点或工具超时；不能承诺立即停机、退费或零费用。

预算台账提供本项目的估算与预留保护，不能代替百炼真实账单，也不能限制其他程序使用同一API产生的费用。

## 五、实际执行过的关键测试

### 本次重新运行的检查

- 后端测试：**160项通过，0项失败**。
- 前端测试：**19项通过，0项失败**。
- 测试范围包含音乐结构、指型、和声终止、时长、速度边界、任务状态、恢复、取消、截止、预算和下载协议等。

以上为本次执行结果，不把历史各轮测试数量相加。生产构建在此前修复记录中通过，保留既有包体积提示；本次报告没有重新执行生产构建。

### 历史真实生成与文件检查

1. **“静夜光”和“晨光微照”**：正式Chrome流程生成与重新生成成功，均为四小节、72 BPM、C调；内容不同，速度和调性保持一致。两份MP3实际时长均约15.34秒，PDF均一页。通过解码、谱面查看和下载文件一致性检查。但用户认为单调、没有练习欲望，音乐吸引力未通过。
2. **“晨光片段”**：四小节、72 BPM、C调，实际音频约15.90秒。检查到C–F–G–C进行、属到主解决、完整主和弦及旋律主音结尾；音频、PDF和下载检查通过。单个成功样本不代表普通提示词稳定成功。
3. **“Warm Motif in C”**：四小节、72 BPM、C调，实际音频约15.94秒；36个旋律音，其中15个十六分音符，共45个音符。检查过动机变化、和声、指型、音频和下载。这一轮同时发现并修复了谱面声部解析问题；不能将旧服务上的样本成功算作该修复已完成正式入口复验。
4. **分阶段样本“夜灯”**：九小节、68 BPM，70个音符；音乐规则和指型检查通过，实际MP3约34.37秒。PDF因执行环境限制没有完成，本样本不是完整交付通过。
5. **分阶段明亮主题样本**：八小节，音乐与音频导出通过；PDF受同类环境限制，流水线保留失败记录并清理半成品，不能作为成功作品验收。
6. **分阶段样本“旧信笺”**：十四小节、66 BPM、C大调，99个音符，音乐和指型检查通过；未完成音频/PDF导出。悲伤描述没有被直接等同于小调。

这些是代表性样本，不是成功率统计。本报告没有足够数据给出平均生成时长、稳定成功率或单曲实际费用。

### 失败与边界检查

- 历史三次生成失败查到和声不合格、跨小节结构或延音线问题；没有交付半成品。不是统一归因于API密钥或PDF。
- 增加结构约束后，又有一轮三个普通提示词全部失败，涉及和声、结构与音高范围。这促成分阶段生成方案；该历史轮次不能作为当前成功率。
- 不合法谱面明确拒绝，没有用空白PDF冒充成功。
- 无效密钥、零预算、网络中断、已有调用后失败均有诊断或自动检查依据。
- 60与120 BPM允许；59.999、120.001及非有限数值拒绝。首次明确输入50或600 BPM在调用模型前拒绝。
- 重新生成时文字要求600 BPM，仍保持原72 BPM；历史50或130 BPM作品拒绝重新生成，不自动改变旧作品。
- 不支持的明确调性在调用模型前拒绝；不能偷偷换成另一调性交付。
- 文件缺失、响应丢失、重复请求、排队取消、取消早于提交、截止及交付前取消均被检查。

### 恢复与取消的受控页面验证

独立内置浏览器诊断页面完成了生成中刷新恢复同一任务、取消后可再创作、成功作品恢复，以及重新生成中保留旧作品。人为让服务端接收提交后返回错误，页面能够通过“恢复当前任务”找回原任务，没有另建任务。

诊断中发现过失败状态被工作线程覆盖的问题，修复后再次取消验证正确。该页面明确不调用模型，复用历史作品，因此只计为恢复与状态逻辑验收，不计为Chrome真实AI生成验收。

## 六、用户人工审阅结果

1. 最初两段作品：用户会指弹，判断“没有难弹的地方”；同时认为听感单调、不符合主题，没有练习动力。**指型初审通过，音乐吸引力不通过。**
2. 后续加入功能和声、终止、力度变化、十六分音符和动机发展后，用户表示“暂时通过吧，先把第一版做出来”。**音乐方向获得阶段性认可。**
3. 再次修复生成后，用户反馈“我觉得听感好很多了”。**听感改善获得认可。**

尚未记录最新版代表作品的重新弹奏审阅，也没有持续练习或教学对照记录。因此不能声称已经证明初学者愿意长期练习，或学习效率得到提高。

## 七、缺陷处理与剩余风险

已修复的必须处理项包括：刷新恢复、提交结果不确定时的任务找回、等待上限与取消、60–120 BPM限制、可用调性约束、失败步骤与调用记录。对应代码与自动检查已完成。

仍需在最终验收前补齐：

1. **最新版完整交付**：若未复验，仍可能出现音乐检查通过但谱面、音频或下载环节失败，用户拿不到作品。
2. **普通提示词连续验证**：历史出现过连续失败，当前不能以少数独立样本推断已经稳定。需要记录每次结果与失败阶段。
3. **真实重新生成与恢复组合**：确认正式服务上旧作品不会丢失，新作品的谱面、音频和下载始终一致。
4. **最新版人工试听和弹奏**：自动规则只能检查部分音乐和演奏限制，仍可能主题不贴切、旋律缺乏吸引力，或实际弹奏不自然。

可以作为后续迭代记录：更丰富的和声与非和弦音处理、伴奏织体、跨小节延音、演奏表现和音色，以及更多风格样本。当前规则较保守，不能承诺已达到用户提到的音乐人的作品水准。

## 八、最后一轮可亲自操作的验收清单

先在原启动窗口停止服务，再双击项目中的“启动音乐伙伴.command”，保持窗口打开；使用Chrome访问`http://127.0.0.1:8000/`。下面正常生成与重新生成会实际调用模型并产生费用，应按已有预算台账执行，失败时先记录原因，不反复盲点。

1. **输入边界**：首次输入“50 BPM，简单吉他指弹小品”。应明确提示60–120 BPM范围，不能开始模型生成。60与120 BPM应通过速度输入限制，但最终仍要满足其他音乐与导出规则。
2. **正常生成**：分别尝试温暖安静、明亮轻快、略带忧伤的普通描述，以及一个自己的描述。每次记录提示词、任务编号、结果和失败信息。成功时应同时看到作品信息、六线谱、音频播放器和两个下载按钮。
3. **播放与文件**：完整播放一首；下载MP3和PDF，用本机播放器及PDF阅读器打开。音频应不超过60秒、结尾自然；谱面应有完整小节和结束，没有空白或裁切；标题、速度和调性应与页面一致。
4. **整段重新生成**：记下旧作品的速度、调性和旋律，要求换一种音乐内容。等待中旧作品仍能查看；成功后内容不同，速度和调性不变，谱面、音频、下载全部切换到同一新作品。
5. **刷新恢复**：分别在生成中、作品成功后刷新。生成中应恢复原任务而非新建任务；成功后应恢复同一作品与下载入口。
6. **取消**：有旧作品时开始重新生成，再点击取消。应结束待生成状态，旧作品仍可试听、下载，并允许再次创作。取消不保证立即中断正在进行的外部请求。
7. **弹奏与听感**：用户按谱弹奏代表作品，检查指型是否自然、旋律与伴奏是否协调，试听是否符合主题，以及是否愿意把它当作短期练习作品。将意见与具体作品对应记录。

若上述最新版流程出现问题，应先定位失败阶段并修复，再复验受影响部分。全部通过且用户明确认可代表作品后，才能把最终结论更新为“本地第一版验收通过”。
