# 分阶段音乐生成修复（2026-10-10）

## 问题与实现

原流程让通用文本模型一次输出全曲音高、时值与音乐技术字段，两次完整候选无法稳定满足和声规则，普通内置示例全部失败。新流程保留同一真实Qwen服务，使用分阶段生成，不引入固定曲目、随机模板或不合格结果的替代。

1. AI规划标题、动机与发展、BPM、调性和每小节和弦级数。检查功能方向、V到I/i终止、57秒演奏预算和重新生成的速度/调性约束。
2. 程序依据调性、标准定弦、前五品与跨度生成可用和弦指型/旋律音域清单。它是乐理与乐器约束，不包含预写旋律。AI选择每小节的指型和音符；程序只将所选项转换为实际音高，不修改音符以掩盖错误。
3. 逐小节AI创作四拍节奏单元与旋律音序列。节奏单元包括四分、八分、十六分、附点八分与休止；每拍单元长度固定一拍，程序计算起止位置，避免模型做节奏总和算术。携带此前两个实际小节及实际音高，让动机重复和发展有上下文。
4. 单步检查失败仅重试该步骤一次，不重新生成已通过小节；规划/小节各至多两次。最终再次检查全曲功能和声、终止、指型、时长，然后导出同一源的MP3与PDF。
5. 所有请求沿用原预算台账、地域配置、网络错误处理和有限重试。记录每个成功/拒绝步骤的安全调用凭据、费用与错误阶段；认证/预算/网络失败不会被当作音乐纠错无限重试。

主文件：backend/app/providers/staged.py；共用受预算约束JSON传输位于qwen.py；pipeline.py正式入口默认分阶段提供商；原接入诊断与注入式单元测试保留。

## 范围与限制

- 本轮稳定性优先：当前新生成采用调内三和弦、和弦音旋律，伴奏采用AI所选指型的持续和弦。暂不让模型自由生成七和弦、非和弦音、跨小节连音与复杂分解伴奏；通用作品结构和历史作品仍支持其既有合法内容。这是明确的生成范围，不等同音乐学认为只能这样写。
- 八分/十六分与附点节奏、动机发展仍由AI选择，不保证好听或适合每个主题；人工听感和试弹必须保留。
- 候选指型清单优先前五品，使用有界可用音域；某些调性/和声没有可用终止时明确拒绝，不暗自转调或变速。重新生成保持原BPM和调性。
- 通常一个规划加逐小节调用，速度比一次整曲调用慢。规划最多16小节，单步最多两次，加上每次HTTP的既有有限重试仍是有界流程，预算在每个请求前检查。
- 独立进程中的PDF浏览器无法启动，必须以本机正式服务验证实际PDF导出，不能用假的PDF验收。

## 验证记录

136项后端测试通过：包含C大调/A小调真实音符和声与指型检查、节奏转换保持所选音高/时值、错误节奏不补写、单步纠错而不重写全曲、末尾同音区导音解决、重新生成速度/调性约束、预算/认证失败不进行音乐重试、安全失败凭据保存等。

独立真实调用“温暖安静”生成“夜灯”，9小节、68 BPM，实际功能/指型通过，无高品位，跨度3、换把1，完整MP3导出34.369887秒。真实“轻快明亮”8小节也通过音乐与音频导出阶段，但独立环境PDF浏览器失败，因此这两次不是完整页面验收。真实“略带忧伤”也通过最终音乐检查，标题“旧信笺”，14小节、66 BPM、C大调，99个音符，无高品位，跨度3、换把1；情绪提示不等同于小调，不能把本次记为真实小调验收。该次尚未导出音频/PDF。

正式服务重启后的三个普通示例、重新生成、试听与两类下载复验仍待执行。136项自动测试与独立模型成功结果不代替正式页面端到端验收。本轮未宣称生成问题已经完全解决，也未确认新的音乐听感通过。
