# 任务07：六线谱诊断

状态：2026-10-10完成转换器、共用谱面组件和诊断页面；固定短/长样例在本机Chrome验证通过。没有新增正式创作首页、音频或下载。

## 改动与用途

- `backend/app/music/alphatex.py`：把主数据转换为alphaTex，保留音高、弦位、时长与同时发声的关系；空白处补休止，不挪动音符。旋律和伴奏是独立谱面声部，伴奏中的持续低音需要时分到额外谱面声部。
- `backend/scripts/export_tablature_diagnostics.py`：从固定两小节样例生成2小节和16小节两组诊断数据，源JSON和排谱文本成对保存在前端公开诊断文件；不是AI作品。
- `frontend/src/components/Tablature.tsx`：共用alphaTab谱面组件；完整排谱、禁用播放器和延迟渲染，显示加载与失败状态，卸载时释放实例。
- `frontend/src/diagnostics/TablatureDiagnostics.tsx`：切换短/长样例，显示作品信息、完整六线谱和原始数据核对入口。
- `backend/app/main.py`：提供明确的诊断页面入口，避免直接访问返回404。
- `frontend/vite.config.ts`、依赖文件：锁定alphaTab及其Vite插件1.7.1，处理音乐字体与构建资源。本机使用现有Node24运行，未强制忽略依赖兼容错误；alphaTab1.8.4插件要求Vite7/8，本次保留现有Vite6并验证1.7.1组合。
- `frontend/scripts/check-tablature.mjs`、后端测试：用真实alphaTab解析生成文本，逐音核对，不只看转换后的文本是否含某个数字。

依据[官方多声部语法](https://alphatab.net/docs/alphatex/structural-metadata)，先输出一个声部的全部小节，再输出下一个声部全部小节。[官方Vite安装说明](https://www.alphatab.net/docs/getting-started/installation-vite)解释了字体和构建插件的用途。主数据与alphaTex使用“一弦为最高弦”，alphaTab内部模型反向编号，检查器已换算后核对；不要直接把内部弦号回写主数据。

## 亲自验证

服务运行时，在Chrome打开：

`http://127.0.0.1:8000/diagnostics/tablature`

1. 默认看到“短样例：2小节”、80 BPM、C major、标准定弦和六线谱；页面明确标注固定诊断样例、非AI。旋律每拍一音，伴奏低音每两拍一音，在同一小节中同时弹奏。
2. 对照 `指型规则与人工审阅.md` 中的逐拍说明，第一小节旋律为一弦0/3品、二弦1品、一弦0品；低音为五弦3品和四弦2品。第二小节对应Am样例。
3. 点击“长样例：16小节”，共16小节；向下滚动，看到最后第16小节、结束线和“全部谱面结束 · 16小节”，谱面没有被卡片裁掉。再切回短样例，没有旧谱叠在新谱上。
4. 展开“核对原始音乐数据和排谱文本”，查看与该谱面对应的源数据。

未运行服务时双击根目录 `启动音乐伙伴.command`，然后打开相同诊断路径；启动脚本打开的根路径仍是原有占位首页。开发前端运行于5173时也可以打开其 `/diagnostics/tablature`。

开发检查：后端运行 `scripts/export_tablature_diagnostics.py --check` 验证生成数据同步；前端运行 `node scripts/check-tablature.mjs` 核对真实解析结果。后端48项测试通过，前端构建通过，12/96个诊断音符的弦号、品位、音高、起点和长度逐项一致。

本轮浏览器验证使用原生Chrome；Codex内置浏览器返回 `ERR_BLOCKED_BY_CLIENT`，没有将其失败当作通过，也没有绕过浏览器安全提示。原生Chrome能正常访问本机服务、渲染和切换样例。

## 限制

调性需是明确的大小调写法，如C、C major、A minor；不能无损表示的连音组合或休止长度会明确失败，不把音乐强行串行、截短或移位。当前固定诊断页只服务开发核对，完整作品生成链路属于后续任务。字体和音色资源许可随依赖保留，正式分发仍需在交付说明中保留相应归属。
