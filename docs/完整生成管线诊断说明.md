# 任务11：真实AI到完整作品的生成管线

状态（最新）：2026-10-10普通本机两首真实作品生成成功，已完成产物清单/逐音谱面/实际PDF逐页图片/MP3完整解码验证，79项测试通过，任务11验收完成。人工指弹与听感审阅统一留任务19。

## 改动及作用

- `backend/app/providers/qwen.py`：保留任务04的接入诊断，另增加正式创作模式，向模型说明57秒演奏上限、确认的指型限制和旋律加伴奏要求；修正时给出具体问题，不用固定样例替代AI。
- `backend/app/music/pipeline.py`：真实模型候选→基础检查→指型分配→同一主数据→alphaTex/MIDI/MP3/PDF。最多两次音乐候选请求（首次加一次修正）；每次供应商网络请求仍沿用已实现的预算预留和最多两次网络尝试。认证、预算、网络失败不会触发额外作曲修正；导出失败也不会重新调用模型。
- 每次生成使用独立的 `runtime/jobs/<任务编号>`。产物先放临时目录，全部检查通过后移到 `artifacts`，最后才把 `manifest.json` 标为ready并列出文件大小、SHA256和共同作品编号。失败标为failed、保留阶段及安全错误、删除半成品目录；不影响已有成功作品。
- `backend/scripts/check_pipeline.py`、`检查完整生成.command`：本机真实诊断入口；检查打印服务就绪后才付费调用模型。默认用两种描述生成两首作品，输出每首任务编号及目录；`--inspect`仅检查已有成品，不调用AI。
- `backend/tests/test_pipeline.py`：隔离验证修正上限、错误阶段、半成品清理、空白PDF拒绝、旧作品保留及完整产物清单。测试替身只用于自动测试，不能作为真实模型/音频/PDF验收证据。
- `frontend/scripts/check-tablature.mjs`：可传入一个任务目录，用真实alphaTab解析器逐音核对该AI作品；原短/长诊断检查继续可用。

## 用户亲自验证

1. 保持 `http://127.0.0.1:8000/` 的本机服务运行，网络可用。
2. 在桌面 `music companion` 文件夹双击 **检查完整生成.command**。这会真实调用已配置的千问模型并计入200元预算，没有新增网页按钮。
3. 成功时，两首各输出 `status: ready`、`job_id`、`composition_id`、BPM、音频长度、PDF页数及产物目录。最后显示 **任务11真实完整生成通过**。有任何“整体生成失败”都不能作为完成，失败会指出具体阶段。
4. 打开输出的 `runtime/jobs/<job_id>/artifacts`，应有 `composition.json`、`score.alphatex`、`creation.json`、`music.mid`、`audio.mp3`、`score.pdf` 六个文件。打开MP3应听到吉他，打开PDF应看到完整谱面；作品编号与终端输出一致，音频不超过60秒。
5. 将最后提示或失败阶段告诉我，我会读取生成文件，进一步核对实际PDF逐页版面、MIDI和谱面音符一致性。人工指弹与听感审阅按已确认安排统一在任务19，不将自动规则当成人工可演奏结论。

高级命令（在项目根目录）：

```sh
backend/.venv/bin/python backend/scripts/check_pipeline.py --prompt '温暖安静，适合夜晚弹奏'
backend/.venv/bin/python backend/scripts/check_pipeline.py --inspect '<替换为实际任务编号>'
```

完整默认诊断的成功清单写在 `runtime/diagnostics/pipeline-check.json`；单次失败保存在对应任务的 `manifest.json`。只查看或核对已有产物不会再调用模型。反复双击完整生成入口会发起新创作并产生费用。
