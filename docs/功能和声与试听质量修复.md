# 功能和声与试听质量修复（任务19，首版暂时通过）

依据用户确认的要求：小片段也要有调性与功能和声逻辑、紧张到解决，结尾主和弦和旋律主音；不能堆砌无逻辑音符。本轮补充实际音符检查，修复此前仅检查结构与指型的不足。

## 实现范围

- harmony.py解析大/小调、常见三和弦与七和弦及和弦内转位低音；当前数据每小节只支持一个声明和弦，不支持小节内换和弦、复杂借用和弦或副属体系。这是当前实现范围，不是通用音乐理论限制。
- 检查实际根音、三音及声明七和弦的七音；和声伴奏使用和弦音，开始低音支持声明的根音/转位。主/下属/属功能按调内和弦解释，本轮拒绝属功能直接回下属的进行；不规定所有作品必须同一种和弦循环。
- 本轮末尾用原位V或V7到原位I/i；连接处的实际导音上行半音到同音区主音，持续至连接处的属七音下行到主和弦三音。
- 最后旋律音为主音；其起奏时真实发声的音符必须构成完整原位主三和弦，共同持续到最后小节结束。只有主音、和弦标签正确或最后硬改字段都不能通过。
- 旋律非和弦音只接受本轮有限可验证的相邻级进经过/辅助、倚音、延留、先现等处理。该检查保守，尚不覆盖完整声部进行、所有非和弦音或所有风格，不称为完整教授级和声分析。
- 对新候选在指型分配前后均检查；检查失败回传实际问题，最多按已有次数修正，最终不合格不交付；不自动补写/改写模型音乐。旧作品保留为历史验收证据，不冒称符合新规则。
- MIDI不再所有音符同力度：旋律高于伴奏，按强拍、旋律高点和句尾做确定性的拨弦力度变化。不改变音高、时值、BPM或调性，不加入随机错拍或变速。这是基础演奏层次，尚不等同真人表现。
- creation.json记录和声检查、乐句结构诊断与演奏策略，便于复核。试听好听与否、主题表达与练习意愿仍由用户判断。

## 理论参考与产品取舍

[Open Music Theory：Harmonic syntax](https://openmusictheory.github.io/harmonicSyntax1.html)说明调性乐句中主、下属、属到主的功能组织；[Performing a harmonic analysis](https://openmusictheory.github.io/harmonicAnalysis.html)强调分析不只是标和弦名称。本轮采用属到主终止，是对用户所要求明确收束的实现选择，并不宣称所有音乐都必须这样结束。
